## Objective

Ship Still 2.1.0 to Chrome, Firefox, iOS/iPadOS and macOS, built from `main` so the packages include
the Facebook Page Reels-tab fix, with the new store screenshots.

## Completed

- **Facebook Page Reels-tab fix, #213 (merged).** Still's hide rule made Facebook's tab row
  treat the tab as overflowed, so the tab flickered in and out of view. The fix hides the tab's
  contents instead, plus the "More" menu entry and the empty feed "Reels" header. The rule set is
  1.1.10, re-signed with the dev key. Not done: a production-signed rule set for existing
  installs (needs the production key and a Supabase push).
- **Store screenshots, #216 (merged).** They're in `docs/release/screenshots/store-ready/`,
  one folder per store. The upload order, sizes and AMO captions are in that folder's `README.md`.
  - iPhone 6.9": 7 images (1320×2868)
  - iPad 13": 3 images (2064×2752)
  - Mac: 6 images (2880×1800)
  - Chrome: 5 images (1280×800)
  - Firefox: 5 images (1280×800)
  - Instagram: 3 posts (1080×1350)
- **Screenshot pipeline** in `docs/release/screenshots/source/frames/`:
  - `capture*.mjs` capture the pages and browser windows.
  - `annotate.js` draws the red marks, taken from `seed.json`.
  - `frames.json`, `frames.html` and `render-frames.mjs` compose each image.
  - `tests/playwright/showcase-frames.spec.ts` checks every image's size and bans forbidden claims.
- **Retired 2.0 images** moved to `docs/release/screenshots/archive/2.0/`.

## Blockers and human gates

- **macOS signing:**
  - The local profile "Mac Team Provisioning Profile: com.chartash.still" lacks the iCloud
    capability and the `com.apple.developer.ubiquity-kvstore-identifier` entitlement.
  - The fix (Xcode automatic signing, or `-allowProvisioningUpdates`) changes the Apple Developer
    account, so it needs owner approval.
- **iOS archive:** `archive.sh` needs `ASC_KEY_ID`, `ASC_ISSUER_ID` and `ASC_KEY_PATH`, which
  are not present. The alternative is Xcode Organizer.
- **Store uploads and submissions:** owner actions.
